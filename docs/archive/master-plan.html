1 · Executive verdict

A high‑quality PDF guide — but 0% of the app exists yet

What's in the repo is small, careful, and correct in spirit: a tested Python diagram pipeline and a genuinely distinctive teaching method. But it produces a PDF, covers only 3×3 up to 2‑look CFOP, and contains no JavaScript, no TypeScript, no HTML output, and no PWA groundwork. The content is ~1/5 of the target curriculum; the platform is at zero. The good news: the hard-won assets (pedagogy, diagrams, alg verification) transfer cleanly into the app plan below.

The three headline answers

Do we use JS or TS at the moment? No. The repo is 100% Python (diagram generator + cube simulator), Markdown, Lua (Pandoc filter), and Typst config. There is no web code at all — an earlier HTML output path was deliberately removed to keep the build PDF‑only.

Should we switch? Yes — for the app. A PDF can't be an installable, offline‑first, interactive PWA, so the product needs a web codebase, and in 2026 that means TypeScript (strict): it's the ecosystem default (all major frameworks scaffold TS; ~72% of frontend job listings ask for it; the TC39 "types in JS" proposal is still Stage 1, so a build step is required either way), and cubepath's fiddliest parts — algorithm data, cube state, SRS scheduling — are exactly where types pay off. The Python code is not wasted: it stays as build‑time tooling (diagram generation, PDF companion) — details in §6.

How far along are we? Content ≈ 20% (beginner→2‑look CFOP done well, with 3 correctness bugs found in this audit — one real coverage gap). Full CFOP ≈ 15%, 4×4 and 5×5 at 0%, platform at 0%. The realistic framing: the project so far produced an excellent seed and a validated pedagogy; the product itself starts now.

What deserves to survive the rewrite

Three assets are better than anything the big reference sites offer and must carry over unchanged in spirit:

  • The phased method. Beginner → CFOP with no "throw away what you learned" cliff: Phase 2 switches last‑layer order with just 2 new algorithms, Phase 3 completes 2‑look with 8 more, and nearly every alg reuses known triggers. No mainstream site structures the transition this deliberately.
  • Machine‑verified correctness. Every published algorithm runs through a simulator in CI. Extended (see F4), this becomes the app's superpower at 145+ cases: no hand‑maintained case can silently rot.
  • The visual language. Consistent top‑view case diagrams + isometric step/notation diagrams, generated from code — ready to scale to full OLL/PLL sets programmatically.
3 · Audit findings

Four verified issues in the current content

Found by cross‑checking the guide's cases against its own bundled simulator (all claims below were reproduced mechanically, not by eyeballing). None of these diminish the approach — but F1/F2 are learner‑facing and worth fixing even before the app work starts.

✕F1 · Coverage gap The H case (OLL 21) has no algorithm — Phase 3's "one algorithm per case" promise is broken for it

Phase 3 claims every OLL/PLL case is solved in one algorithm. Classifying the six taught corner‑orientation algs against the seven canonical OCLL twist cases (Sune, Anti‑Sune, H, Pi, U, T, L) shows they cover exactly six — no taught alg solves H (all four corners twisted, yellow "headlights" on both sides). A learner hitting H must fall back to Phase 2's Sune‑chaining, contradicting the phase's premise.

Evidence: exhaustive simulator classification (each guide alg × each canonical case × all AUF/rotation offsets). Fix: add H — R U R′ U R U′ R′ U R U2 R′ — verified to solve exactly the double‑headlights state.

✕F2 · Diagram ↔ algorithm mismatch The "Headlights" entry pairs an H‑case picture with a U‑case algorithm

The shipped oll_headlights.svg (and its caption "0 yellow, headlights L+R") depicts the H case. But its algorithm R2 D R′ U2 R D′ R′ U2 R′ actually solves the U case (OLL 23) — two back corners already oriented, headlights facing the solver. A learner holding the pictured case and running the printed alg will not orient the corners.

Evidence: applying the alg's inverse to a solved cube in the repo's simulator yields 2 yellow‑up corners + front headlights — not the pictured 0‑up, left/right‑headlights state. Fix: keep the existing picture for the new H entry (it matches H exactly), and draw a new U‑case diagram for the R2 D… alg.

◐F3 · Wrong caption "Chameleon — 2 diagonal yellow" is actually the adjacent case

Chameleon (T case) and Bowtie (L case) are both captioned "2 diagonal yellow" in Phase 3. Simulator check: Chameleon's two oriented corners are adjacent; only Bowtie's are diagonal. Recognition text is the one thing a learner leans on mid‑solve — captions need a full audit pass.

Evidence: inverse‑alg state inspection — Chameleon yellow‑up corners {BR, FR} (adjacent); Bowtie {BR, FL} (diagonal).

◐F4 · Test blind spot Tests verify each alg against its own inverse — so picture/alg drift is invisible

The alg tests construct each case by inverting the alg under test, then confirm the alg solves it. That's self‑consistent by construction and can never catch F2‑style mismatches between the diagrammed state and the alg. The architectural fix (and a core principle for the app): derive every case picture from its algorithm — one source of truth, mismatch impossible — instead of hand‑defining sticker layouts.

Evidence: tests/test_algorithms.py pattern; F2 passed CI precisely because of it.

5 · Product vision

The niche is genuinely open

Research across the teaching/training landscape shows a clear gap: the best free resources (JPerm, Ruwix) are static pages + YouTube with no course structure, no offline story, and no retention system; the only product bundling lessons + 3D + spaced repetition (CuberPal) is iOS‑only at ~$40/year. Nobody offers free + structured + interactive + offline‑first. That's the slot cubepath fits — with a pedagogy the others don't have.

Five pillars of "amazing"

  • One unbroken ladder. Absolute zero → beginner → 2‑look → full CFOP → 4×4 → 5×5, applying the no‑dead‑zone principle at every seam (full PLL learned as upgrades of 2‑look cases; 4×4 framed as "your 3×3 + two new skills + parity"; 5×5 as "4×4 skills, but centers are fixed again").
  • Interactive everything. Every step, case, and algorithm gets a scrubbable 3D player (tap to play, drag to rotate, stage‑aware sticker dimming) plus the static case icon; notation taught by tapping moves, not reading tables.
  • Offline‑first, installable. The entire course precached on first visit; WCA‑quality scrambles generated on‑device; installs to the home screen; works in airplane mode. Nothing in the app ever needs a server.
  • Practice that sticks. Per‑case trainer with realistic case frequencies, recognition‑only drills, FSRS spaced repetition for algorithm retention, local progress with export — the paid‑app feature set, free.
  • Terse and dense. Keep the repo's writing philosophy: minimal prose, maximal signal, no 20‑minute videos. The anti‑YouTube cube site.

Licensing & naming (cleared)

Algorithms themselves are procedures/facts — not copyrightable (US Copyright Office Circular 33); every site shares the same T‑perm. What is protected is others' prose, videos, and imagery — cubepath writes its own words and generates its own diagrams, so it's clean. "Rubik's" remains a live trademark (Spin Master): keep branding as "cubepath — speedcubing from zero", use generic "3×3 cube" phrasing in product copy. Third‑party PDFs already correctly gitignored. cubing.js is dual MPL‑2.0/GPL — the MPL option is web‑app friendly with no copyleft over app code.

cubing.js — the one dependency that needs respect

It does everything (3D player, alg parsing, kpuzzle state math, WCA scrambles, even Bluetooth smart‑cubes later) — but it's pre‑1.0 with experimental* APIs, and its web‑worker loading is the classic failure point under bundlers. Pin the version, apply the known Vite config, and gate releases on an offline E2E test:

<!-- A PLL case demo: player shows the case, plays to solved -->
<twisty-player
  alg="R U R' U' R' F R2 U' R' U' R U R' F'"
  experimental-setup-anchor="end"
  experimental-stickering="PLL"
  background="none" control-panel="bottom-row">
</twisty-player>

// astro.config.mjs → vite options (known-good cubing.js setup)
vite: {
  optimizeDeps: { exclude: ["cubing"] },
  worker: { format: "es" },
  build: { target: "es2022" },
}

4×4/5×5 render via its puzzle‑geometry engine (puzzle="4x4x4"). Budget ~250–400 KB gz extra on player pages (three.js) — a one‑time precache cost, irrelevant offline. License: choose the MPL‑2.0 option.

7 · Architecture

One data source feeds everything

The audit's core lesson (F2/F4): hand‑maintained case definitions drift. The app inverts this — a single typed algorithm/case dataset from which pages, players, icons, trainers, tests, and the PDF are all derived. A mismatch becomes a build error, not a shipped bug.

algs.ts — single source of truth ~145 cases: id · group · name · recognition text · alg variants · setup · stickering mask · probability · phase/prereqs

8 · PWA blueprint

Offline‑first, verified in CI — not hoped for

The site is finite (a few MB with icons and player code), so the right strategy is the simple one: precache everything on first visit; after that the app never needs the network again. Verified iOS/Android behavior as of mid‑2026 below — several popular blog claims are outdated.

Caching & updates

  • Precache all of it — pages, CSS/JS, case SVGs, fonts, and cubing.js worker chunks (globPatterns incl. wasm); scrambles then work in airplane mode.
  • Update UX: registerType: "prompt" — never reload mid‑lesson; show "New version — refresh" toast via virtual:pwa-register; plus a one‑time "Available offline" toast.
  • Storage: progress/SRS in IndexedDB (idb); call navigator.storage.persist() on first meaningful interaction; offer JSON export/import as belt‑and‑braces.
  • CI gate: Playwright E2E: load once → context.setOffline(true) → navigate a lesson, scrub a player, generate a 3×3 + 4×4 scramble. This single test protects the product promise.

Install reality, mid‑2026

  • iOS 26 / Safari 26: every site added to the Home Screen now opens as a web app by default; manifest + SVG icons honored. Still no beforeinstallprompt → show a small "Share → Add to Home Screen" hint for iOS visitors.
  • iOS storage: installed web apps get browser‑class quota (up to ~60% of disk/origin) and, once persisted, are excluded from eviction — the old "7‑day wipe" fear doesn't apply to installed+persisted apps. EU users unaffected (Apple's 2024 EU PWA removal was reversed before shipping).
  • Android/desktop: full install support; custom install button via beforeinstallprompt.
  • Hosting note: SW + precache needs header control (Cache-Control on sw.js) — a reason for Cloudflare over GitHub Pages.
9 · Roadmap

Seven milestones, each shippable on its own

Ordered so the PWA promise is locked in early (M2) and every later milestone inherits it. Sizes are relative effort (S < M < L) assuming Claude Code does the heavy lifting and you review. Fix‑first: the three content bugs get patched before anything else so the current PDF stays trustworthy.

Quick wins — this week, in the current repo

M0S

Foundation — scaffold, prove, deploy

Restructure repo (app/, tools/diagrams/, guide/); Astro 7 + TS strict; <twisty-player> island proof on 3×3 and 4×4/5×5; algs.ts schema v1 seeded with the current 16 algs; CI (ruff + pytest + Vitest + Playwright); first deploy to Cloudflare.

Done when: a live URL scrubs a T‑Perm on 3×3 and an OLL‑parity alg on 4×4, and CI is green.

M1M

3×3 course online — the existing guide, made interactive

Port Phases 1 → 3 into MDX lessons: every step gets a player (case → solved), every alg a tap‑to‑play; interactive notation page; new "cube anatomy / absolute zero" onboarding module; per‑case pages generated from algs.ts; PDF companion still builds.

Done when: a stranger can go from scrambled to solved to 2‑look CFOP entirely on the site, and every published alg is Vitest‑verified.

M2S

PWA — offline‑first locked in

@vite-pwa/astro precache‑everything; update + offline‑ready toasts; iOS install hint, Android install button; storage.persist(); manifest + icons; Playwright offline E2E gating deploys.

Done when: airplane‑mode phone: full course, players, and fresh scrambles all work; installs to home screen on iOS and Android.

M3L

Full CFOP — the big content build

Intuitive F2L lessons (discovery‑first, then the 41‑case reference); full PLL (21) as upgrades from 2‑look; full OLL (57) grouped by shape with recognition text; cross planning + inspection; finger tricks; lookahead. Diagram generator scales by deriving all case states from algs. "Learn next" ordering from prereqs.

Done when: all 119 CFOP cases have page + icon + player + verified alg(s), reachable through a coherent course path.

M4M

Practice layer — what makes it stick

Alg trainer (per‑case status: unlearned/learning/finished; case‑filtered scrambles; balanced vs realistic frequencies); recognition‑only drills; FSRS reviews (ts-fsrs) with a daily queue; progress dashboard; JSON export/import.

Done when: you can drill exactly the 6 PLLs you're learning, offline, and tomorrow the app knows which ones you're about to forget.

M5L

Big cubes — 4×4 then 5×5

4×4: centers (no fixed centers! color‑scheme from corners), 2‑then‑3‑2‑3 edge pairing, wide/layer notation, 3×3 stage, OLL + PLL parity with the 25/25/25/25 probability framing ("parity is expected, not broken"), Yau as the advanced track. 5×5: centers via bars, freeslice pairing, last‑2‑edges (12 cases), single parity alg, and why there's no PLL parity. All on PG3D players; parity algs verified on 4×4/5×5 kpuzzle.

Done when: both courses are complete and a 3×3 solver can finish a 5×5 using only the site.

M6M

Polish & reach — v1.0

Light timer (ao5/ao12, session stats — not a csTimer clone); printable credit‑card cheat sheets from algs.ts (the old TODO, finally cheap); landing page, SEO/OG cards; i18n scaffold (EN first, DE ready); optional streaks from SRS. Backlog beyond v1: smart‑cube support via cubing/bluetooth, community alg voting, 1v1 races.

Done when: v1.0 is public, installable, and something you'd post on r/Cubers without a disclaimer.
